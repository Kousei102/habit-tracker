# フェーズと受け入れ基準

このファイルが builder と reviewer の**唯一の正典**です。実装の根拠も合否の根拠も、常にここに書かれた受け入れ基準（AC）です。

- **[E2E]** … reviewer が Playwright で実ブラウザ検証する
- **[単体]** … builder が `node:test` で書き、reviewer が実行を確認する
- 印のないもの … reviewer がコマンド実行・コード確認・DB 確認で検証する

builder はこのファイルを変更できません。AC の記述が曖昧だと感じた場合は、自分の解釈で実装を進め、完了報告にその解釈を明記してください。

---

## Phase 1: 足場

npm workspaces、TypeScript 設定、Hono サーバー、SQLite マイグレーション、Vite クライアントの疎通まで。

- **AC-1.1** リポジトリのクリーンな状態から `npm install` が成功する
- **AC-1.2** `npm run dev` でサーバー（:3001）とクライアント（:5173）が同時に起動する
- **AC-1.3** `GET /api/health` が HTTP 200 で `{"ok":true}` を返す
- **AC-1.4** サーバー起動時に `DB_PATH` の SQLite ファイルが生成され、`users` / `sessions` / `habits` / `entries` の 4 テーブルが存在する
- **AC-1.5** マイグレーションが冪等である。サーバーを 2 回起動してもエラーにならず、スキーマが重複しない
- **AC-1.6** DB 接続時に `PRAGMA foreign_keys` が `1` になっている（SQLite の既定は OFF なので明示設定が必要）
- **AC-1.7** **[E2E]** ブラウザで `/` を開くとページが表示され、クライアントが取得した `/api/health` の結果が画面に描画される
- **AC-1.8** `npx tsc --noEmit` が client / server 双方で通る

## Phase 2: 認証

パスワード認証とセッション。単一ユーザー運用だが、`user_id` による絞り込みは最初から入れる。

- **AC-2.1** `npm run seed-user` が `.env` の `ADMIN_USER` / `ADMIN_PASSWORD` からユーザーを作成する。既存ユーザーなら パスワードを更新する
- **AC-2.2** 未認証で `GET /api/habits` を叩くと 401 が返る
- **AC-2.3** 正しい資格情報での `POST /api/auth/login` が、`HttpOnly` かつ `SameSite=Lax` の Cookie を発行する
- **AC-2.4** 誤ったパスワードでの login が 401 を返し、レスポンス本文がユーザー名の存在有無を漏らさない
- **AC-2.5** DB の `users.password_hash` に平文パスワードが含まれていない
- **AC-2.6** **[E2E]** 未認証で `/` を開くとログイン画面が出る
- **AC-2.7** **[E2E]** ログインするとダッシュボードが表示され、リロードしてもログイン状態が保持される
- **AC-2.8** **[E2E]** ログアウトするとログイン画面に戻り、その後リロードしてもダッシュボードは表示されない

## Phase 3: 習慣 CRUD と今日の記録

- **AC-3.1** **[E2E]** チェック式（`boolean`）の習慣を作成すると一覧に表示される
- **AC-3.2** **[E2E]** 数値式（`numeric`、目標値と単位つき）の習慣を作成すると、実績と目標が読み取れる形（例「0 / 30 分」）で表示される
- **AC-3.3** **[E2E]** チェック式の習慣をトグルして達成にすると、ページをリロードしても達成のままである
- **AC-3.4** **[E2E]** 数値式の習慣に目標未満の値を入力すると未達成表示、目標以上の値を入力すると達成表示になる。いずれもリロード後に保持される
- **AC-3.5** **[E2E]** 習慣の名前と目標値を編集すると一覧に反映される
- **AC-3.6** **[E2E]** 習慣を削除すると一覧から消える。ただし DB の `entries` にその習慣の記録が残っている（論理削除）
- **AC-3.7** 存在しない `habit_id` への `PUT /api/entries/:habitId/:date` が 404 を返す（他ユーザーの習慣も同様に 404 で、存在を漏らさない）
- **AC-3.8** `PUT /api/entries/:habitId/:date` が同じ日付に二度呼ばれても行が重複せず、値が上書きされる

## Phase 4: 統計（ストリークと達成率）

**現在ストリークは、今日が未達成でも途切れさせない。** 今日はまだ終わっていないため、today が未達成なら昨日から遡って数える。

- **AC-4.1** `npm test` の stats 単体テストが全て通る
- **AC-4.2** **[単体]** 今日が未達成でも、昨日まで 3 日連続で達成していれば現在ストリークが 3 になる
- **AC-4.3** **[単体]** 今日を含めて 3 日連続で達成していれば現在ストリークが 3 になる
- **AC-4.4** **[単体]** 記録が 1 件も無い習慣で、現在ストリーク 0 / 最長ストリーク 0 / 達成率 0% が返り、例外にならない
- **AC-4.5** **[単体]** 途中に未達成の日を挟むと現在ストリークがそこで止まり、最長ストリークには過去の最長区間が残る
- **AC-4.6** **[単体]** 数値式の習慣で、目標未満の日は達成としてカウントされない
- **AC-4.7** **[E2E]** 時刻を固定した状態で過去 5 日分（今日を含む）の達成をシードすると、画面に現在ストリーク 5 が表示される
- **AC-4.8** **[E2E]** そのうち 1 日を未達成にすると、現在ストリークが正しく短くなって表示される
- **AC-4.9** **[E2E]** 直近 30 日の達成率が期待値どおりに表示される
  - 分母は **`today` を含む固定 30 日**。習慣の作成日ではクランプしない。`habits.created_at` はサーバーの壁時計なので、時刻を固定した E2E では作成日が未来になり、クランプすると破綻する
  - パーセントは整数丸め。分子と分母（`13%（4 / 30 日）`）も併記し、表示値を検算可能にする

## Phase 5: 年間ヒートマップ

実装前に `dataviz` スキルを読むこと。

- **AC-5.1** **[E2E]** 直近 1 年分のヒートマップが描画され、セル数が 7 行 × 52〜53 列の範囲にある
- **AC-5.2** **[E2E]** 記録のある日のセルが、記録の無い日のセルと異なる塗りになっている
- **AC-5.3** **[E2E]** 数値式の習慣で、目標に対する達成割合が高い日ほど濃い塗りになる（少なくとも 3 段階が区別できる）
- **AC-5.4** **[E2E]** 各セルが日付と値を含むアクセシブルネームを持つ（スクリーンリーダーと `getByRole` の双方から辿れる）
- **AC-5.5** **[E2E]** ビューポート幅 375px でページ本体（`document.body`）が横スクロールしない。ヒートマップ自身のコンテナ内だけがスクロールする
- **AC-5.6** **[E2E]** ライトモードとダークモードの双方で、記録なしのセルと最も薄い記録ありのセルが異なる色として描画される
- **AC-5.7** 外部のチャートライブラリを追加していない（SVG を直接描いている）
