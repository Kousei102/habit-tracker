# フェーズと受け入れ基準

このファイルが builder と reviewer の**唯一の正典**です。実装の根拠も合否の根拠も、常にここに書かれた受け入れ基準（AC）です。

- **[E2E]** … reviewer が Playwright で実ブラウザ検証する
- **[単体]** … builder が `node:test` で書き、reviewer が実行を確認する
- 印のないもの … reviewer がコマンド実行・コード確認・DB 確認で検証する

builder はこのファイルを変更できません。AC の記述が曖昧だと感じた場合は、自分の解釈で実装を進め、完了報告にその解釈を明記してください。

## ⚠ Phase 7 以降でサーバーを廃止しました

Phase 1〜6 はクライアント + Node サーバー + SQLite の構成で完成し、全て PASS しています
（記録は `.harness/reviews/`）。その後、**恒久的に無料でホストできること**が要件として
確定したため、Phase 7 でサーバーを撤去し、データをブラウザの localStorage に移しました。

**Phase 1〜6 の AC は履歴として残しますが、次のものは既に無効です。** これらが満たされて
いないことを理由に FAIL にしないでください。

| 無効になった AC | 理由 |
|---|---|
| AC-1.2 / AC-1.3 / AC-1.4 / AC-1.5 / AC-1.6 | サーバーと SQLite が存在しない |
| **Phase 2 の全て（AC-2.1〜2.8）** | 認証を廃止。静的サイトには認証する相手が無く、データは端末内にしかない |
| AC-3.6 の「DB の `entries` に記録が残っている」 | 論理削除の要件自体は AC-7.7 に引き継ぐ |
| AC-3.7 / AC-3.8 | HTTP API が存在しない |
| AC-6.1 / AC-6.6 | Node での配信と環境変数が存在しない |

これら以外の AC — 習慣 CRUD、今日の記録、ストリーク、達成率、ヒートマップ、エラー表示、
レスポンシブ — は**全て有効なまま**で、Phase 7 以降も満たし続ける必要があります。

## Phase 2: 認証

パスワード認証とセッション。単一ユーザー運用だが、`user_id` による絞り込みは最初から入れる。

## Phase 3: 習慣 CRUD と今日の記録

- **AC-3.1** **[E2E]** チェック式（`boolean`）の習慣を作成すると一覧に表示される
- **AC-3.2** **[E2E]** 数値式（`numeric`、目標値と単位つき）の習慣を作成すると、実績と目標が読み取れる形（例「0 / 30 分」）で表示される
- **AC-3.3** **[E2E]** チェック式の習慣をトグルして達成にすると、ページをリロードしても達成のままである
- **AC-3.4** **[E2E]** 数値式の習慣に目標未満の値を入力すると未達成表示、目標以上の値を入力すると達成表示になる。いずれもリロード後に保持される
- **AC-3.5** **[E2E]** 習慣の名前と目標値を編集すると一覧に反映される
- **AC-3.6** **[E2E]** 習慣を削除すると一覧から消える。ただし DB の `entries` にその習慣の記録が残っている（論理削除）
- **AC-3.7** 存在しない `habit_id` への `PUT /api/entries/:habitId/:date` が 404 を返す（他ユーザーの習慣も同様に 404 で、存在を漏らさない）
- **AC-3.8** `PUT /api/entries/:habitId/:date` が同じ日付に二度呼ばれても行が重複せず、値が上書きされる

## Phase 4: 統計（ストリークと達成率）

**現在ストリークは、今日が未達成でも途切れさせない。** 今日はまだ終わっていないため、today が未達成なら昨日から遡って数える。

- **AC-4.1** `npm test` の stats 単体テストが全て通る
- **AC-4.2** **[単体]** 今日が未達成でも、昨日まで 3 日連続で達成していれば現在ストリークが 3 になる
- **AC-4.3** **[単体]** 今日を含めて 3 日連続で達成していれば現在ストリークが 3 になる
- **AC-4.4** **[単体]** 記録が 1 件も無い習慣で、現在ストリーク 0 / 最長ストリーク 0 / 達成率 0% が返り、例外にならない
- **AC-4.5** **[単体]** 途中に未達成の日を挟むと現在ストリークがそこで止まり、最長ストリークには過去の最長区間が残る
- **AC-4.6** **[単体]** 数値式の習慣で、目標未満の日は達成としてカウントされない
- **AC-4.7** **[E2E]** 時刻を固定した状態で過去 5 日分（今日を含む）の達成をシードすると、画面に現在ストリーク 5 が表示される
- **AC-4.8** **[E2E]** そのうち 1 日を未達成にすると、現在ストリークが正しく短くなって表示される
- **AC-4.9** **[E2E]** 直近 30 日の達成率が期待値どおりに表示される
  - 分母は **`today` を含む固定 30 日**。習慣の作成日ではクランプしない。`habits.created_at` はサーバーの壁時計なので、時刻を固定した E2E では作成日が未来になり、クランプすると破綻する
  - パーセントは整数丸め。分子と分母（`13%（4 / 30 日）`）も併記し、表示値を検算可能にする

## Phase 7: サーバーの撤去とローカル保存

サーバーと認証を廃止し、データをブラウザの localStorage に移す。**この段階では機能を
足さない。** 保存先が変わっても Phase 3〜6 の振る舞いが一切変わらないことが要件。

エクスポート / PWA は Phase 8 で扱う。ここで先回りして作らないこと。

- **AC-7.1** `server/` が存在しない。`package.json` の workspaces から server が消え、クリーンな状態から `npm install` が成功する
- **AC-7.2** `npm run build` の出力が静的ファイルのみで、実行に Node プロセスを必要としない。`client/dist` を任意の静的ファイルサーバーで配信して動作する
- **AC-7.3** **[E2E]** ページ読み込み後の操作（習慣の作成・記録・削除）を通して、**`/api/` へのネットワークリクエストが 1 件も発生しない**
- **AC-7.4** **[E2E]** ログイン画面が存在しない。`/` を開くと直接ダッシュボードが表示される
- **AC-7.5** **[単体]** ストレージ層は**同期 API** である。保存した値をそのまま読み出せる（往復テスト）
- **AC-7.6** **[単体]** 保存データにスキーマ版番号が入っている。未知の版・壊れた JSON・空文字列を読んだとき、例外で画面が落ちず、既存データを黙って破壊しない
- **AC-7.7** **[E2E]** Phase 3 の振る舞いが保持される。チェック式・数値式の作成、今日の記録、編集、削除、**リロード後の保持**。削除は論理削除のままで、削除した習慣の記録は残り続ける（Phase 8 のエクスポートに含まれる必要があるため）
- **AC-7.8** **[E2E]** Phase 4 の統計が同じ値を表示する。現在ストリーク・最長ストリーク・直近 30 日の達成率
- **AC-7.9** **[E2E]** Phase 5 のヒートマップが同じ規則で描画される。セル数、記録あり / なしの塗り分け、目標比による濃淡、アクセシブルネーム
- **AC-7.10** **[E2E]** 新しいブラウザコンテキストでは空の状態から始まる（データが端末ローカルであることの確認）
- **AC-7.11** **[E2E]** 習慣 10 個 × 5 年分（18,250 件）を投入した状態でも、ダッシュボードとヒートマップが表示され、リロード後も保持される
- **AC-7.12** **[E2E]** 保存に失敗したとき（localStorage の容量超過など）、**無言で失敗せず**ユーザーが読めるエラーが出る（AC-6.4 の継承）
- **AC-7.13** `shared/` に移した統計の単体テストが全て通る。`computeHabitStats` / `computeStats` の**中身は変更しない**（純粋関数なので移動だけで済むはず。変更したなら完了報告に理由を書く）
- **AC-7.14** **[E2E]** 375px / 768px / 1280px でレイアウトが破綻しない（AC-6.5 の継承）

## Phase 8: PWA とデータの持ち出し

**このフェーズの目的はデータを失わないこと。** サーバーが無くなった以上、バックアップは
存在しない。想定端末は **iPhone (iOS Safari)**。

WebKit は「7 日間サイトを操作しないと localStorage / IndexedDB を削除する」と定めており、
**ホーム画面に追加した web アプリだけがこの対象外**になる。つまり PWA 化はデータ保護の
手段そのものであって、体裁の問題ではない。

- **AC-8.1** `manifest.webmanifest` がビルド成果物に含まれ、HTML からリンクされている。`name` / `short_name` / `start_url` / `display: "standalone"` / `theme_color` / `background_color` と、**192px と 512px の icons** を持つ
- **AC-8.2** iOS でホーム画面に追加したときスタンドアロン表示になる指定がビルド後の HTML に含まれている（`apple-touch-icon` を含む）
- **AC-8.3** **[E2E]** Service Worker が登録され、**オフライン状態（`context.setOffline(true)`）でもアプリが起動し、習慣を記録できる**
- **AC-8.4** `navigator.storage.persist()` を要求する。拒否されても動作は継続する
- **AC-8.5** **[E2E]** エクスポートすると JSON ファイルがダウンロードされる。**削除済みの習慣とその記録を含め**、全ての習慣と記録が含まれる
- **AC-8.6** **[E2E]** エクスポートしたファイルを、データを全消去したあとにインポートすると、習慣・記録・統計・ヒートマップが**完全に復元される**
- **AC-8.7** **[E2E]** インポートは適用前に内容の要約（習慣数・記録数・期間）を表示し、明示的な確認操作を経てから反映される。**ネイティブの `confirm()` は使わない**（Playwright が既定でダイアログを dismiss するため、テストできない実装になる）
- **AC-8.8** **[E2E]** 壊れた JSON / このアプリのものではない JSON をインポートしようとすると、**既存データを破壊せずに**ユーザーが読めるエラーを出す
- **AC-8.9** **[E2E]** 最後にエクスポートした日付が画面から読み取れる。一度もしていなければそれが分かる
- **AC-8.10** README に、iPhone でホーム画面に追加する手順と、**追加せずに使うとデータが 7 日で消えうること**が書かれている
- **AC-8.11** **[E2E]** 375px でレイアウトが破綻せず、エクスポート / インポートに到達できる
- **AC-8.12** **[E2E]** 保存データが壊れて読めない状態でも、**画面からインポートまたは初期化に到達できる**。想定端末は iPhone で devtools が使えず、Safari では単一サイトの localStorage だけを消すのが困難なため、「壊れたら詰み」は許容しない。初期化は誤操作で発火しない形にすること

## Phase 9: リマインダーとアイコンバッジ

**時刻指定のプッシュ通知はこの構成では実装できない。** 通知を送る主体としてサーバーと
VAPID 鍵が必要で、GitHub Pages にそれは置けない。ローカルで時刻を待てる
`Notification Triggers` は未出荷、`Periodic Background Sync` は iOS 非対応、
`setTimeout` + `showNotification()` はタブが生きている間しか動かない（iOS は
バックグラウンドの PWA を停止する）。**サーバーを足す形の実装は Phase 7 の到達点を
破棄することなので、ここでは選ばない。**

代わりに、サーバー無しで実際に「気づける」2 つだけを扱う。**未達成の表示**（アプリを
開いたとき）と、**アプリアイコンのバッジ**（`navigator.setAppBadge()`。アプリを閉じた
あともホーム画面に数字が残る、アプリの外から気づける唯一の手段）。

iOS では Badging API に**通知の許可が必要**で、`Notification.requestPermission()` は
**ユーザー操作起点でしか呼べない**。したがってバッジは明示的なボタンによる opt-in と
し、許可が下りない環境では画面内の表示だけに劣化させる。**バッジが使えないことが
アプリの不具合として現れてはいけない。**

- **AC-9.1** **[単体]** 未達成の判定が `shared/domain.ts` の `isAchieved()` のみを経由する。記録が無い日は未達成として数える。チェック式 / 数値式（目標あり・なし）/ NaN を網羅
- **AC-9.2** **[単体]** 習慣が 0 件のときリマインダーは何も言わない。全て達成しているときは達成した旨を言う（`exportReminder()` と同じ「言うことが無ければ黙る」規約）
- **AC-9.3** **[E2E]** 未達成の習慣があるとき、未達成の件数と習慣名が画面から読める
- **AC-9.4** **[E2E]** 最後の未達成習慣を記録すると、リロードを挟まずに表示が達成状態に変わる
- **AC-9.5** **[E2E]** バッジは**明示的なボタン操作**で opt-in する。ページを読み込んだだけでは `Notification.requestPermission()` が呼ばれない
- **AC-9.6** **[E2E]** 許可されたあと、未達成の件数が `navigator.setAppBadge(n)` に渡される。記録して 0 件になるとバッジが消される
- **AC-9.7** **[E2E]** 許可が拒否されたとき、バッジは有効にならず、拒否されたことが画面から読める。**アプリは動き続け、未処理の例外が 1 件も出ない**
- **AC-9.8** **[E2E]** `navigator.setAppBadge` が存在しない環境でも、非対応であることが画面に出るだけで、アプリは通常どおり動く
- **AC-9.9** **[E2E]** バッジの有効・無効はリロードをまたいで保持される。保存先は文書とは別のキーで、**インポートでも初期化でも失われない**（文書のバイト列も変わらない）
- **AC-9.10** **[E2E]** 日付が変わると、未達成の件数とバッジが新しい日の値に切り替わる
- **AC-9.11** **[E2E]** 保存データが読めない状態ではリマインダーを表示せず、バックアップへの到達（AC-8.12）を妨げない
- **AC-9.12** **[E2E]** 375px でレイアウトが破綻せず、バッジのボタンに到達できる

## v1 で意図的に外すもの

以下は AC に含めない。実装されていなくても FAIL にしない。

- 曜日スケジュール（「平日のみ」「週 3 回」）
- 週次ふりかえりサマリ
- **時刻指定のプッシュ通知**（「毎晩 21 時に通知する」）— 送信する主体としてサーバーが
  必要で、恒久的に無料の静的ホストという要件と両立しない。`Notification Triggers` は
  未出荷、`Periodic Background Sync` は iOS 非対応。代替として Phase 9 で未達成の表示と
  アイコンバッジを扱う
- ユーザー登録画面 / マルチユーザー UI
